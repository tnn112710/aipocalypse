# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"aipocalypse" — a PC first-person shooter built in Unity **6000.6.2f1** (Unity 6) with URP 17.6. There is no CLI build/lint/test pipeline; development happens in the Unity Editor (compile happens on editor focus/domain reload). The `*.csproj`/`*.slnx` files at the repo root are generated by Unity — never edit them.

The `unity-mcp` tools (`mcp__unity-mcp__*`) can drive the running editor (read console, run scenes, capture views, manage assets/scripts) — use them to check compile errors and verify changes instead of guessing. Tests, if added, use `com.unity.test-framework` (Test Runner window / `unity-test-runner` skill).

## Where things live

- `Assets/_Game/` — **all first-party game code and content go here.** Core gameplay lives under `Assets/_Game/_Core/`, split by system: `EnemySystem`, `InputSystem`, `PlayerSystem`, `WeaponSystem`, and `_Common/Utils`. Also `Materials`, `Models`, `Prefabs`, `Scenes`. (Currently scaffolding — folders exist but are still mostly empty, so establish conventions here rather than looking for them.)
- `Assets/_StoreAssets/` — third-party art/asset-store content (Synty Polygon Generic/Prototype, Low Poly Weapon Bundles 1–3, Stylized Grass/Water 3, Damage Numbers Pro, Feel). Treat as vendor code: don't modify; reference or make variants/prefabs under `_Game`.
- `Assets/Plugins/` — third-party editor/runtime tooling (Odin Inspector, DOTween/Demigiant, GPUInstancerPro, etc.). Don't modify.
- `Assets/Settings/` — URP assets (`PC_RPAsset`, `PC_Renderer`), volume profile, and Input System config.
- `Assets/Scenes/SampleScene.unity` — the only scene in Build Settings so far. `Assets/_Game/Scenes` is intended for real game scenes (add them to Build Settings when created).
- `Packages/` — local packages: A* Pathfinding Project (`com.arongranberg.astar`) and GPU Instancer Pro (`com.gurbu.gpui-pro` + prefab/terrain modules).

## Key tech choices (from `Packages/manifest.json`)

- **Input**: new Input System only (`activeInputHandler: 1`). Actions asset is `Assets/Settings/InputSystem_Actions.inputactions` with a `Player` map: Move, Look, Attack, Interact, Crouch, Jump, Previous, Next, Sprint. Use these actions; don't call the legacy `UnityEngine.Input`.
- **Enemy AI / navigation**: A* Pathfinding Project is present, alongside `com.unity.ai.navigation` and `com.unity.behavior` (Unity Behavior graphs). Pick one navigation stack per feature deliberately.
- **Camera**: Cinemachine 6.6 is installed.
- **Rendering/perf**: URP, GPU Instancer Pro for foliage/props, VFX Graph, Splines, Terrain Tools.
- **Editor conveniences**: Odin Inspector (`Sirenix`), DOTween, Feel (MoreMountains), Damage Numbers Pro are available for game code.

## Keeping docs current

- When you add or change a core system (data structures, gameplay flow, system boundaries), update the relevant section of this file or `docs/` in the same change. Keep this file high-level; put detail in `docs/`.
- `docs/gdd/` — game design. Design intent: `docs/gdd/GDD.md` (split into per-topic files here as it grows). `docs/gdd/IDEAS.md` is a draft scratchpad, not canon — never implement from it unless explicitly asked.
- `docs/technicals/` — technical docs. Architecture and data flow: `docs/technicals/ARCHITECTURE.md`. Why choices were made: `docs/technicals/DECISIONS.md`.
- Current milestone/tasks: `docs/ROADMAP.md`.
- A Stop hook (`.claude/hooks/check-docs.sh`) reminds once when `Assets/_Game/**/*.cs` changed without doc updates.

## Code style

- No XML/docstring blocks. At most one short `//` line on a method to state its purpose; skip it when the name is self-explanatory.
- Don't add comments narrating a fix or adjustment ("changed X to Y", "fixed bug"). Comment only for important/critical fixes, workarounds, or non-obvious solutions, and explain the *why*.

## Conventions / gotchas

- Commit messages in history use the style `+ add <thing>` (e.g. `+ add synty prototype`).
- `.gitattributes` is the standard Unity template with Git LFS for binary asset types; make sure LFS is installed before committing/pulling large assets.
- Always commit `.meta` files together with their assets; never delete/rename asset files outside the Unity Editor (or move the `.meta` alongside) or GUID references break.
- Main branch is `develop`.
